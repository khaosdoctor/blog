# Links do mês

### [Criando um chat só com Vanilla JS](https://bit.ly/3mlhpE6)

Nesse pequeno tutorial a gente consegue ver como é importante a ideia de delegar o que você não quer fazer pra outros lugares. Esse exemplo mostra que é possível usar bibliotecas inteiras e terceirizar grande parte do código para plataformas como o Twillio para criar um chat completo usando só JavaScript clássico

### [Aprendendo algo novo tecnicamente](https://muratbuffalo.blogspot.com/2021/12/learning-technical-subject.html)

Artigo super legal do Murat que ensina um pouco sobre como você pode aprender um novo assunto técnico e o que funciona para ele.

A maioria de nós é o que chamamos de messy learners, que são pessoas que tem um caminho mais tortuoso de aprendizado, assim como ele, entre os tópicos que ele menciona estão:

-   Criar contexto para aprender, porque a maioria de nós aprende quando temos muito contexto sobre o que estamos aprendendo
-   Aprender fazendo e cometendo erros
-   Revisitar várias vezes o mesmo tópico

### [As coisas mais difíceis na ciência da computação](https://bit.ly/3P3yb7e)

Esse artigo é parecido com um outro artigo que eu vi no mês passado. Neste aqui exploramos alguns tópicos a mais.

-   Invalidação de cache: é com certeza uma das coisas mais chatas e mais difíceis que todos nós um dia vamos passar. Quando a gente tem que invalidar um cache? Qual é o momento correto? E tudo isso são perguntas muito complexas de responder (pelo menos é a conclusão que todos nós chegamos)
-   Nomear coisas: Aqui é mais do mesmo do que eu falo quase sempre, é muito difícil ler código de quem programa achando que o outro lado é um computador, então um dos principais problemas é a comunicação e nesse artigo ele levanta dois problemas legais: usar palavras diferentes para falar da mesma coisa, e usar palavras iguais para falar de coisas diferentes
-   Datas e timezones: Isso eu pessoalmente tenho um grande problema até perceber que datas são somente pontos no tempo e horas são somente contadores até serem atribuídos com um timezone. Realmente trabalhar com essas duas constantes acaba sendo muito mais difícil
-   Estimativas: Estimar o desenvolvimento do software é a coisa mais complicada de todas, segundo o autor a gente erra porque não conseguimos prever os problemas e porque a natureza de uma estimativa é uma opinião que leva em conta todo um contexto
-   Sistemas distribuídos: Vai ter uma série no meu canal só sobre isso de tão complicado que é. Mas nesse artigo o autor cita Leader election e Dual Writes como sendo os principais problemas que ele enfrentou

### [A história do Svelte](https://bit.ly/3uK3ZWS)

### [Como ambientes de desenvolvimento ficaram complicados](https://bit.ly/3ALUqu9)

Esse artigo fala como antigamente os ambientes de desenvolvimento eram mais simples e como a composição de ferramentas ao invés de usar uma única ferramenta pode ser melhor do que usar uma única ferramenta, mas também levanta vários problemas como o fato de que shells podem precisar mudar para entender mais o que a gente está digitando ao invés de só executarem os comandos.

### [Quando deveríamos usar Map ao invés de Objects no JavaScript](https://bit.ly/3RpJXup)

Um artigo super interessante que diz que os maps deveriam ser usados mais do que eles são, principalmente nos casos onde temos dicionários ou hashmaps com números variáveis de entradas, tipo um event emitter.

Além disso o Map é mais performático do que um objeto nas operações e consome menos memória.

Em suma os objetos deveriam ser utilizados somente quando você tem um número fixo de propriedades.

### [Melhores formas de instalar pacotes globais no NPM](https://bit.ly/3yZx82G)

Nesse artigo o Dr. Axel explora 5 jeitos de instalar pacotes globais no NPM:

-   Mudando o npm prefix do pacote
-   Instalando diretamente no diretório home ao invés do diretório global
-   Instalando em um subdiretório do Home
-   Usando o NPX
-   Usando um gerenciador de versões (NVM, ASDF, etc)
